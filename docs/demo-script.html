  • Queries Nimbus_Account__c by name → sums unpaid Nimbus_Invoice__c
  • Deterministic balance lives in code, not the LLM

Flows (all AutoLaunched)

  • Nimbus_Preview_Plan_Change — read-only resolve/validate
  • Nimbus_Commit_Plan_Change — write, sets Current_Plan__c

  • Nimbus_Outage__c — Region, Status, Summary, Est_Resolution, Is_Active
  • Case (standard) — troubleshoot handoff target

What is not used — and why

CapabilityStatusRationale
Data CloudNot usedNot provisioned in sdo (DataKnowledgeSpace = 0). No capability here needs it.
Data Library / ADLNot usedNo document corpus. Nothing to index.
RAG / vector retrievalNot usedDeliberate. All grounded data (outages, plans, invoices) is structured and keyed — a deterministic query is the correct, auditable tool. Reaching for RAG over structured data would be a red flag.
Prompt Template actionNot usedGenerative troubleshooting guidance comes from the subagent's own reasoning; no separate template needed for the demo scope.
Roadmap note (worth saying aloud): RAG earns its place only when troubleshooting guidance moves from model-general knowledge to a real Nimbus knowledge base of unstructured articles. That's the one place a Data Library + retrieval would be the right tool — and it's scoped as future work, not shoehorned in now.
